= Body JSON Router
:toc: left
:toc-title: Contents
:toclevels: 3
:sectnums:
:revdate: 2026-03-30
:source-highlighter: highlight.js
:icons: font

A reference application that routes incoming HTTP POST requests to different
nginx upstream pools based on fields extracted from the JSON request body.
The routing decision is made with *zero whole-body buffering in JS* — nginx
streams `r->request_body` directly to the chosen upstream via `proxy_pass`.

== Overview

The router scans the JSON request body for two routing fields using a
stateful streaming scanner, consults a routing table, and calls
`req.pass(backend)` to hand off the request to one of four internal nginx
relay locations.

.Default routing table
[cols="2,2,2",options="header"]
|===
|`service` |`tenant.region` |Backend

|`payments` |`eu-west` |`/internal/payments-eu/`
|`payments` |`us-east` |`/internal/payments-us/`
|`analytics` |(any) |`/internal/analytics/`
|(anything else) |(any) |`/internal/default/`
|===

== Architecture

=== Request flow

....
Client POST /route/
  │
  ├─[Phase 1: sync, zero I/O]──────────────────────────────────────────────┐
  │  req.bodyPreread                                                         │
  │  bytes already in the TCP recv buffer (same segment as request headers) │
  │  scanner.feed(preread)                                                   │
  │  scanner.done() ? → req.pass(backend)  ─────────────────────────────── │ ── ► proxy_pass
  └─[Phase 2: async, minimal buffering]────────────────────────────────────┘
     for await (chunk of req.bodyChunks()) {
       scanner.feed(chunk)
       if (scanner.done()) break   ← stop as soon as fields are found
     }
     req.pass(backend) ───────────────────────────────────────────────────────► proxy_pass
                                                                                    │
                                                         nginx streams r->request_body
                                                         to upstream natively; JS
                                                         holds no copy of the body.
....

=== Two-phase routing

Phase 1 (sync, zero I/O)::
`req.bodyPreread` returns bytes already in nginx's connection read buffer
beyond the request headers — the "preread" portion that arrived in the same
`recv()` as the request line and headers.  For routing envelopes that fit in
one TCP segment this is the entire body.  `scanner.feed(preread)` is called
synchronously; if `scanner.done()` is true, `req.pass(backend)` is called
before any async I/O starts.

Phase 2 (async, minimal buffering)::
`req.bodyChunks()` yields nginx's native body buffers one at a time.  nginx
has already DMA'd the body into its own buffer chain; JS only holds one chunk
string at a time.  The scanner processes each chunk and exits as soon as
`done()` is true.  Remaining bytes stay in nginx's buffers and flow to the
upstream untouched.

=== Body forwarding via req.pass()

`req.pass(location)` calls `ngx_http_internal_redirect`, which re-enters the
nginx phase engine at the new URI with `r->internal = 1` (enabling access to
`internal;` locations).  The matched location's `proxy_pass` then streams
`r->request_body` to the upstream *natively* — no JS-side body copy, no
`X-Forwarded-Body` header, no header-size limits.

=== Streaming scanner (createPathScanner)

`createPathScanner(paths)` returns a stateful scanner object:

[source,javascript]
----
var s = createPathScanner(['service', 'tenant.region']);

s.feed(chunk);       // process next bytes (resumable across chunks)
s.done();            // true when all paths have been captured
s.getResult();       // {path: value, …} of captured paths
----

The scanner visits each byte exactly once, making it O(n) regardless of body
size.  It is resumable across arbitrary chunk boundaries — a value can span
multiple chunks without any re-scanning.  State labels:

[cols="1,3",options="header"]
|===
|State |Meaning

|`S`  |Start — expect `{`
|`O`  |Object open — expect `"key"` or `}`
|`K`  |Reading key string
|`E`  |Escape in key string
|`:`  |After key — expect `:`
|`V`  |After `:` — dispatch on first byte of value
|`CS` |Capturing string value
|`CE` |Escape in captured string
|`CX` |Capturing scalar (number / bool / null)
|`SS` |Skipping string
|`SE` |Escape in skipped string
|`SX` |Skipping scalar
|`SN` |Skipping nested object/array (depth-counted)
|`NS` |String inside skipped nested
|`NE` |Escape in nested string
|`AV` |After value — expect `,` or `}`
|`D`  |Done — all paths found or object exhausted
|===

.Example: 4 KB body, routing fields near the start
....
{
  "service":  "payments",           ← captured, remain = 1
  "tenant": {
    "id":     "t42",                ← skipped (not needed)
    "region": "eu-west"             ← captured, remain = 0 → STOP
  },
  "payload": { /* 4 KB of data */ } ← scanner exits, never touches this
}
....

The scanner stops immediately when `remain === 0`.  The remaining body bytes
stay in nginx's buffers and are forwarded to the upstream by `proxy_pass`
without any JS involvement.

== Configuration

=== nginx.conf

[source,nginx]
----
js_source  /etc/nginx/router.js;

http {
    upstream payments-eu  { server 10.0.1.10:8080; keepalive 16; }
    upstream payments-us  { server 10.0.1.11:8080; keepalive 16; }
    upstream analytics    { server 10.0.2.10:8080; keepalive 16; }
    upstream default-pool { server 10.0.3.10:8080; keepalive 16; }

    server {
        listen       80;
        server_name  router;   # <-- must be 'router'

        location /route/ {
            # handler assigned by router.js; no client_max_body_size limit
            # needed — body is streamed to upstream, not copied into JS
        }

        location /internal/payments-eu/ {
            internal;
            proxy_pass http://payments-eu/;
        }
        location /internal/payments-us/ {
            internal;
            proxy_pass http://payments-us/;
        }
        location /internal/analytics/ {
            internal;
            proxy_pass http://analytics/;
        }
        location /internal/default/ {
            internal;
            proxy_pass http://default-pool/;
        }
    }
}
----

IMPORTANT: `server_name` *must* be `router`.  `router.js` locates the
virtual server by name, falling back to `servers[0]` when the name is
absent.

=== Routing table (router.js CFG)

All tunables are in the `CFG` object near the top of `router.js`:

[source,javascript]
----
var CFG = {
    /* JSON dot-paths to extract.  Scanner stops once all are found.   */
    routingPaths: ['service', 'tenant.region'],

    /* Routing table — evaluated in order, first match wins.
     * Omitting a key from `match` makes it a wildcard.                */
    routes: [
        { match: { 'service': 'payments', 'tenant.region': 'eu-west' },
          backend: '/internal/payments-eu/' },
        { match: { 'service': 'payments', 'tenant.region': 'us-east' },
          backend: '/internal/payments-us/' },
        { match: { 'service': 'analytics' },
          backend: '/internal/analytics/' },
    ],
    defaultBackend: '/internal/default/',
};
----

Each entry in `routes` matches when *all* listed fields equal their expected
values.  Unlisted fields are ignored.  Add routes with a single `match` key
to create wildcard-on-second-field rules (as the `analytics` entry
demonstrates).

== Body Forwarding

`req.pass(location)` triggers `ngx_http_internal_redirect`, which re-enters
the nginx phase engine at the new URI.  The matched location's `proxy_pass`
streams `r->request_body` to the upstream directly from nginx's buffer chain.
There is no JS-side copy, no `X-Forwarded-Body` header, and no size limit
from header buffers.

The body the upstream receives is identical to what the client sent.

== Error Responses

[cols="1,1,3",options="header"]
|===
|Status |Condition |Body

|`400`
|Empty body or body does not begin with `{`
|`{"error":"body must be a JSON object"}`

|`400`
|`req.bodyChunks()` throws (I/O error)
|`{"error":"could not read body"}`
|===

All other errors (upstream unreachable, etc.) are handled natively by nginx's
`proxy_pass` error-page machinery.

== createPathScanner API

[source,javascript]
----
var scanner = createPathScanner(['service', 'tenant.region']);

// Feed bytes incrementally — call as many times as needed:
scanner.feed(chunk);          // string; resumable across chunk boundaries

// After each feed():
if (scanner.done()) {
    var fields = scanner.getResult();
    // fields['service']       → 'payments'   (string scalar)
    // fields['tenant.region'] → 'eu-west'    (string scalar)
    // fields['missing']       → undefined    (path not found)
}
----

.Supported value types
[cols="1,3",options="header"]
|===
|JSON type |Returned as

|string |JavaScript string (escape sequences decoded)
|number |JavaScript number
|`true` / `false` |JavaScript boolean
|`null` |JavaScript `null`
|object / array |Not captured — treated as "not a routing scalar";
the path will be absent from the result.
|===

.Dot-path syntax
[cols="1,2",options="header"]
|===
|Path |Matches

|`service` |Top-level key `"service"`
|`tenant.region` |Key `"region"` inside top-level object `"tenant"`
|`a.b.c` |Key `"c"` inside `"b"` inside `"a"`
|===

Arrays are not indexed — only object keys are walked.  If a path segment
refers to an array element, the scanner will not find it and the path will
be absent from the result.

== JS-Pilgrim Features Used

[cols="1,2",options="header"]
|===
|Feature |Usage

|`location.handler`
|Async content handler on `/route/` drives the two-phase body scan and calls
`req.pass()`.

|`req.bodyPreread`
|Synchronous getter.  Returns bytes already in nginx's connection read buffer
beyond the request headers.  Phase 1 feeds these bytes to the scanner; if
all routing fields are found here, no async I/O is needed.

|`req.bodyChunks()`
|Async iterator.  Yields nginx's native body buffers one at a time.  Phase 2
feeds each chunk to the scanner and breaks as soon as `scanner.done()` is
true, leaving the rest of the body in nginx's buffers.

|`req.pass(location)`
|Triggers `ngx_http_internal_redirect`.  The new location's `proxy_pass`
streams `r->request_body` to the upstream natively — zero JS-side copy.

|`req.respond(status, headers, body)`
|Sends 400 error responses when the body is missing or not JSON.

|`nginx.log(level, msg)`
|Structured INFO log for each routing decision.
|===
