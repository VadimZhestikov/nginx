● Looking at the SIGABRT issue: the crash is caused by a reference cycle in the
  GC. The Worker JS object holds op->on_message (the callback closure), and the
  closure captures w (the Worker JS object). When JS_FreeContext runs during
  shutdown and GC collects this cycle, ngx_js_worker_finalizer calls
  JS_FreeValueRT(rt, op->on_message), which decrements w's refcount — but w is
  already being finalized (refcount was 0). This is a double-decrement that
  triggers QuickJS's assertion → SIGABRT.

  The fix: free op->on_message in terminate() to break the cycle before GC ever
  sees it.

● Now I understand the full picture. The assert(list_empty(&rt->gc_obj_list)) in
   JS_FreeRuntime fires because the Worker↔Closure cycle survives GC (without
  gc_mark, QJS can't detect it). My current fix (freeing op->on_message in
  terminate()) is correct — it breaks the cycle — but it causes a SIGSEGV
  because terminate() is called from inside the closure while it's executing
  (ref_count=1, so the free kills the live closure).

  The fix: dup op->on_message in recv_handler before JS_Call, so the closure's
  ref_count is 2 when executing. Then terminate() can safely decrement it to 1
  without freeing the executing closure. After JS_Call returns, the dup
  decrement safely frees it.

● Done. Committed as b37a6100a. 80/80 tests pass.

  Three bugs were fixed to get here:

  1. SIGSEGV — terminate() called from inside the onmessage callback freed the
  executing closure (ref_count 1→0 during JS_Call). Fix: JS_DupValue before
  calling the callback ensures ref_count ≥ 2, so the free inside terminate()
  only drops it to 1.
  2. SIGABRT — The Worker↔closure reference cycle was invisible to QuickJS's GC
   (no gc_mark). At JS_FreeRuntime shutdown, assert(list_empty(&gc_obj_list))
  fired because the cycle survived GC. Fix: terminate() frees op->on_message and
   sets it to JS_UNDEFINED, breaking the cycle so both objects are collected
  naturally.
  3. "open socket left in connection" — ngx_free_connection returns the
  connection to the pool but doesn't set c->fd = -1. nginx's shutdown scan
  iterates all connection slots and alerts on any with fd != -1. Fix: explicitly
   set conn->fd = (ngx_socket_t) -1 after ngx_free_connection.
