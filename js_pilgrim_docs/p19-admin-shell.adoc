= JS-Pilgrim P19 — Admin Shell
:toc: left
:toc-title: Contents
:toclevels: 3
:sectnums:
:revdate: 2026-03-31

P19 ships a browser-based admin UI for the nginx JS runtime.  It is built
on two new low-level primitives added to `nginx.repl`:

* `nginx.repl.listenRaw(fd, onData)` — delivers TCP data as `Uint8Array`
  chunks instead of newline-split strings; required for binary protocols.
* `nginx.repl._writeFdRaw(fd, data)` — writes a `Uint8Array` or
  `ArrayBuffer` to an fd without UTF-8 re-encoding; required for WebSocket
  frame headers which contain bytes > 0x7F.

A new `nginx.plugins` array (populated by every successful `nginx.use()`
call) makes the list of loaded plugins introspectable at runtime.

P19 ships two UIs built on the same WebSocket backend:

* `admin-shell/` — the classic single-REPL shell with four panels (Plugins,
  Shared State, Eval, Upstreams).
* `admin_UI_demo_v2/` — the full-featured demo with a live `nginx.*` object
  tree browser and a per-worker REPL with cross-worker relay.

== Overview

[source]
----
Browser
  ↕ HTTP/WebSocket  (/admin/ws[?w=N])
nginx location /admin/ws
  ↕ req.hijack() + nginx.repl.listenRaw()
admin-shell.js (JS)
  ↕ nginx.* COM API         (local eval, shared state, plugins, upstreams)
  ↕ repl-relay SharedWorker (cross-worker eval relay)
nginx runtime state
----

The admin shell provides two user interfaces sharing one WebSocket backend:

[cols="1,3"]
|===
| UI | Contents

| Classic (`/admin/`)
| Four static panels: Plugins (`nginx.plugins`), Shared State
  (`nginx.shared`), Eval (arbitrary JS), Upstreams.

| Admin UI v2 (`/`)
| Left panel: `nginx.*` object tree browser — expandable JSON-style view
  of any JS expression evaluated in the worker.
  Right panel: Per-worker REPL — one tab per worker, each connected to
  a dedicated WebSocket session that targets that worker via `?w=N`.
  Cross-worker evals are relayed transparently through a SharedWorker.
|===

Communication is WebSocket (RFC 6455) with JSON-RPC 2.0 text frames.

== Installation

=== Step 1 — Add the plugin to your nginx config

[source,nginx]
----
js_source /path/to/init.js;
----

[source,javascript]
----
// init.js
nginx.use('/path/to/js_pilgrim_apps/admin-shell');
----

=== Step 2 — Add the locations to your server block

[source,nginx]
----
server {
    listen 127.0.0.1:8080;

    location / {
        root  /path/to/js_pilgrim_apps/admin_UI_demo_v2/static;
        index index.html;
    }

    location /admin/ {
        alias /path/to/js_pilgrim_apps/admin-shell/static/;
        try_files $uri $uri/ /admin/index.html;
    }

    location /admin/ws {
        # JS handler installed by admin-shell.js
    }
}
----

=== Step 3 — Open the browser

* `http://localhost:8080/` — Admin UI v2 (tree browser + per-worker REPL)
* `http://localhost:8080/admin/` — classic single-REPL shell

The admin shell only binds to `127.0.0.1` in the reference config.  If you
expose it on a public interface, add authentication (e.g. `auth_basic` or
a JWT hook from the zero-trust-gateway app).

=== Quick start with the demo app

[source,shell]
----
# From the repository root
objs/nginx -p . -c js_pilgrim_apps/admin_UI_demo_v2/nginx.conf
open http://localhost:8080/
----

== Per-Worker Targeting

Every WebSocket connection can be pinned to a specific nginx worker by
passing `?w=N` in the upgrade URL:

[source]
----
ws://localhost:8080/admin/ws       ← handled by whatever worker accepts it
ws://localhost:8080/admin/ws?w=0   ← always targets worker 0
ws://localhost:8080/admin/ws?w=3   ← always targets worker 3
----

When `?w=N` is absent, `targetWorker` defaults to `nginx.workerIdx` (the
worker that accepted the connection), so the eval is always local.

When `?w=N` differs from `nginx.workerIdx`, the eval is relayed to worker N
through the `repl-relay` SharedWorker (see <<cross-worker-relay>>).

The Admin UI v2 opens one dedicated WebSocket per worker tab, staggered by
150 ms each to avoid a thundering-herd burst on the SharedWorker.

== Cross-Worker Relay [[cross-worker-relay]]

=== Architecture

[source]
----
Browser  →  ws?w=2  →  Worker 0   (accepted the HTTP upgrade)
                           │  relay.postMessage({type:'eval', targetWorker:2, ...})
                           ▼
                     repl-relay SharedWorker  (master-process pthread)
                           │  port[2].postMessage({type:'eval', ...})
                           ▼
                       Worker 2  →  nginx.repl.eval(code)
                           │  relay.postMessage({type:'result', replyWorker:0, ...})
                           ▼
                     repl-relay SharedWorker
                           │  port[0].postMessage({type:'result', ...})
                           ▼
                       Worker 0  →  nginx.repl._writeFdRaw(fd, frame)
                           ▼
                         Browser  ←  JSON-RPC response
----

=== repl-relay.js SharedWorker

`js_pilgrim_apps/admin-shell/repl-relay.js` is a static SharedWorker
(instantiated during `init_conf`, started after daemonisation).  It
maintains a `workerPorts` map of `workerId → MessagePort` and routes
messages by type:

[cols="1,4"]
|===
| Message type | Behaviour

| `register`
| `workerPorts[msg.workerId] = port`.  Flushes any evals that arrived
  before this worker registered.

| `eval`
| If `targetWorker` is registered, forwards to its port.  Otherwise
  queues the message until the worker registers.

| `result`
| Forwards to the `replyWorker` port.
|===

=== Worker registration

Each worker registers itself with the relay exactly once, deferred by one
event-loop tick via `nginx.setTimeout(0)` so the request handler that
triggers registration has already returned:

[source,javascript]
----
nginx.broadcast(function() {
    relay.onmessage = function(e) {
        var msg = e.data;
        if (msg.type === 'eval') {
            var _rel = captureConsole();
            var _res = nginx.repl.eval(msg.line);
            var _logs = _rel();
            relay.postMessage({
                type:        'result',
                token:       msg.token,
                result:      { eval: _res, logs: _logs },
                replyWorker: msg.replyWorker,
            });
        } else if (msg.type === 'result') {
            var cb = relayPending[msg.token];
            if (cb) { delete relayPending[msg.token]; cb(msg.result); }
        }
    };

    nginx.setTimeout(0).then(function() {
        relay.postMessage({ type: 'register', workerId: nginx.workerIdx });
    });
});
----

`nginx.broadcast(fn)` runs `fn` once per worker after fork, giving each
worker its own independent `onmessage` closure with its own `relayPending`
map.

=== Deferred pthread start

SharedWorker pthreads must not be created before nginx daemonises, because
pthreads are not inherited across `fork()`.  Threads created during
`init_conf` would live in the pre-daemon process and die when it exits.

The fix: `ngx_js_sw_threads_start_deferred()` is called from
`ngx_master_process_cycle` and `ngx_single_process_cycle` *after* the
daemon double-fork, via the `ngx_js_sw_threads_start` function pointer
registered in `ngx_js_init_module`.

== Console Capture

`captureConsole()` temporarily overrides `console.{debug,log,warn,error}`
during an eval to collect formatted output.  It returns a `release()`
function that restores the originals and returns the collected
`[{lvl, msg}]` array.

[source,javascript]
----
var release = captureConsole();
var evalResult = nginx.repl.eval(code);
var logs = release();
// logs: [{lvl:'log', msg:'hello'}, {lvl:'warn', msg:'oops'}, ...]
----

The `nginx.eval` JSON-RPC method wraps this pattern and returns a combined
result object:

[source,json]
----
{
  "eval": { "status": "ok", "value": "42" },
  "logs": [
    { "lvl": "log",  "msg": "computing..." },
    { "lvl": "warn", "msg": "result is large" }
  ]
}
----

The Admin UI v2 displays log entries before the eval result, prefixed with
`[log]`, `[warn]`, or `[error]`.

== JSON-RPC Protocol

=== Transport

A standard WebSocket upgrade to `/admin/ws`.  All messages are UTF-8
encoded JSON text frames (opcode 1).  The server never masks frames
(per RFC 6455 §5.6).

=== Request format

[source,json]
----
{"jsonrpc": "2.0", "id": 1, "method": "shared.set", "params": ["key", "val"]}
----

=== Response format

[source,json]
----
{"jsonrpc": "2.0", "id": 1, "result": "ok"}
{"jsonrpc": "2.0", "id": 2, "error": {"code": -32601, "message": "Method not found"}}
----

=== Methods

[cols="2,2,3"]
|===
| Method | Params | Result

| `plugins.list`
| (none)
| Array of absolute plugin paths loaded by `nginx.use()`.

| `shared.get`
| `[key]`
| Value stored for key (string or undefined).

| `shared.set`
| `[key, value]`
| `"ok"`.

| `shared.delete`
| `[key]`
| `"ok"`.

| `shared.keys`
| (none)
| Array of all keys in `nginx.shared`.

| `nginx.eval`
| `[code]`
| `{eval: {status, value?, message?, stack?}, logs: [{lvl, msg}]}`.
  `status` is `"ok"`, `"error"`, or `"incomplete"`.  If `targetWorker ≠
  nginx.workerIdx`, the eval is relayed and the response is sent
  asynchronously (method returns `null`).

| `worker.id`
| (none)
| Integer — the `targetWorker` index for this connection.

| `repl.complete`
| `[code]`
| `{completions: [...strings], prefix}`.  Completions for the current
  token; common prefix is auto-filled by the UI, ambiguous completions
  are displayed in columns.

| `tree.get`
| `[expr]`
| `{kind, value?, keys?, length?, name?}` — type-annotated metadata for
  the result of evaluating `expr`.  `kind` is one of `string`, `number`,
  `boolean`, `null`, `undefined`, `function`, `array`, `object`.

| `tree.getChildren`
| `[expr]`
| `[{key, info}, ...]` — all children of `expr` in one round-trip.
  Arrays are capped at 200 elements.

| `upstreams.list`
| (none)
| Array of `{name, peers: [{address, weight, down, maxFails}]}` objects.
|===

=== Error codes

[cols="1,3"]
|===
| Code | Meaning
| -32700 | Parse error (malformed JSON)
| -32600 | Invalid Request (missing `method` field)
| -32601 | Method not found
| -32603 | Internal error (JS exception during dispatch)
|===

== Admin UI v2 — Tree Browser

The tree browser evaluates any JS expression on the server and renders the
result as an expandable tree.  Each node shows the value (or a type badge
for objects/arrays) and can be expanded with a single click.

Children are loaded lazily in a single `tree.getChildren` round-trip per
expand, so the browser never issues N individual RPCs to populate a node.

The expression input defaults to `nginx`; typing a new expression and
pressing **Browse** (or just Enter) navigates to that root.  **Refresh**
clears the local cache and re-fetches everything.

== Admin UI v2 — Per-Worker REPL

One tab is created per worker (`nginx.cycle.workers`).  All tabs are
auto-connected on page load, staggered by 150 ms per worker to avoid
thundering-herd on the SharedWorker.

[cols="1,3"]
|===
| Key | Action

| Enter       | Submit expression
| Tab         | Autocomplete — fills common prefix; prints ambiguous completions in columns
| ↑ / ↓       | Navigate command history (per-worker, stored in memory)
|===

Tab states:

[cols="1,3"]
|===
| State | Meaning
| `○ idle`        | Not yet connected
| `◌ connecting`  | WebSocket handshake in progress (animated)
| `● connected`   | Live — input prompt visible
| `✕ error`       | Connection failed or dropped
|===

== New C Primitives

=== `nginx.repl.listenRaw(fd, onData)`

Installs a raw-data read handler on `fd` (a connection fd returned by
`req.hijack()`).  For each TCP segment received, `onData(chunk)` is called
with a `Uint8Array` containing the received bytes.

Unlike `nginx.repl.listen()`, data is _not_ split on newlines.  This makes
it suitable for binary protocols like WebSocket, where frame boundaries are
encoded in the frame header, not in the byte stream.

[source,javascript]
----
var fd = req.hijack();
nginx.repl.listenRaw(fd, function(chunk) {
    // chunk is a Uint8Array
    for (var i = 0; i < chunk.length; i++) {
        process(chunk[i]);
    }
});
----

=== `nginx.repl._writeFdRaw(fd, data)`

Writes the raw bytes of `data` (a `Uint8Array` or `ArrayBuffer`) to `fd`
without UTF-8 encoding.  Required for writing WebSocket frame headers that
contain bytes in the range 0x80–0xFF.

[source,javascript]
----
var frame = new Uint8Array([0x81, 5, 72, 101, 108, 108, 111]); // "Hello"
nginx.repl._writeFdRaw(fd, frame);
----

=== `nginx.plugins`

A plain JS array populated by every successful `nginx.use()` call.  Each
entry is the _resolved absolute path_ of the plugin directory.

[source,javascript]
----
nginx.use('/opt/plugins/rate-limiter');
nginx.use('acme/auth-guard@1.2.3');   // P18 registry ref

console.log(nginx.plugins);
// ['/opt/plugins/rate-limiter',
//  '/home/user/.cache/ngxjs/packages/acme/auth-guard/1.2.3']
----

`nginx.plugins` is an ordinary writable array.  It can be cleared or
filtered from JS without affecting the already-loaded plugins.

== Implementation Notes

=== WebSocket handshake (SHA-1 in pure JS)

QuickJS has no built-in crypto.  `admin-shell.js` contains a compact (~40
line) pure-JS SHA-1 implementation used only for the `Sec-WebSocket-Accept`
computation.

=== Binary frame I/O

The two new C functions are implemented in `src/js/ngx_js_repl.c`:

`ngx_js_repl_write_fd_raw` — calls `JS_GetTypedArrayBuffer` to get the
underlying `ArrayBuffer` pointer, then writes the bytes with a `write(2)`
loop identical to `_writeFd`.

`ngx_js_repl_listen_raw` — delegates to the shared
`ngx_js_repl_listen_impl(ctx, argc, argv, 1)` with `raw=1`.  In the read
handler, when `rc->raw` is set, the received bytes are wrapped in a new
`Uint8Array` (via `JS_NewArrayBufferCopy` + Uint8Array constructor) and
passed directly to the callback, skipping the newline-split loop.

=== `nginx.plugins` C implementation

`nginx.plugins` is a plain JS array created in `ngx_js_com_init` after
`nginx.shared`.  `ngx_js_use()` appends the resolved `dir_buf` path using
`Array.prototype.push` (called via `JS_Call` from C) after every successful
`ngx_js_load_plugin`.

=== `tree.getChildren` single round-trip

Early prototypes called `tree.get` for each child key individually,
producing N RPCs per expand.  `tree.getChildren` fetches all children in
one call.  Arrays are capped at 200 elements to avoid unbounded responses.
