= JS-Pilgrim P5 — Generator Body Filter
:toc: left
:toc-title: Contents
:toclevels: 3
:sectnums:
:revdate: 2026-03-30

Upgrade `addBodyFilter` to accept async generator functions.  The generator
receives the response body as an async-iterable `chunks` argument; iterating
with `for await` yields one string per buffered chunk.  It may `await` I/O
between yields, and may `yield` any number of output strings.

== Concept

Prior to P5, `addBodyFilter` accepted only:

* a synchronous whole-body function (`'wholeBodySync'`) — receives body, returns string,
* an asynchronous whole-body function (`'wholeBodyAsync'`) — receives body, returns Promise<string>,
* a synchronous streaming function (`'streamingSync'`) — called per chunk,
* an asynchronous streaming function (`'streamingAsync'`) — called per chunk.

P5 adds a fifth mode: **async generator**.  The generator is called once per
request.  Its first argument (`chunks`) is a single-element iterable containing
the complete buffered body as a string.  The generator may `yield` any number
of output strings; they are concatenated to form the new body.

....
request body (buffered)
       ↓
async function*(chunks, req) {
    for await (var chunk of chunks) {
        yield chunk.toUpperCase();  // may have multiple yields per chunk
        await nginx.setTimeout(0);  // may suspend between yields
        yield '!';
    }
}
       ↓
output body = concat(all yielded strings)
....

== API

=== Auto-detect form (recommended)

Pass a single async generator function — no mode string needed.  The
implementation detects `AsyncGeneratorFunction` via `fn.constructor.name`:

[source,javascript]
----
location.addBodyFilter(async function*(chunks, req) {
    for await (var chunk of chunks) {
        yield chunk.toUpperCase();
    }
});
----

=== Explicit mode string

[source,javascript]
----
location.addBodyFilter('generator', async function*(chunks, req) {
    for await (var chunk of chunks) {
        yield chunk;
        yield '\n';
    }
});
----

=== Parameters

[cols="1,1,3"]
|===
| Parameter | Type | Description

| `chunks`
| Iterable<string>
| Single-element iterable `[wholeBodyString]`.  Iterate with
  `for await (var chunk of chunks)` to receive the complete buffered body
  as one string.  `for await` works on sync iterables, so no async overhead
  is incurred when the body is already available.

| `req`
| NginxRequest
| The current request object (read access to headers, method, URI, etc.).
|===

=== Yield values

[cols="1,3"]
|===
| `yield string`
| Appended to the output buffer.

| `return` / fall-through
| Generator done; accumulated output is sent.

| `throw` / unhandled rejection
| nginx logs the error and closes the connection.
|===

=== Async suspension

`await` inside the generator suspends the output pipeline.  The request hold
count is incremented for the duration; nginx resumes the generator when the
awaited Promise settles (same mechanism as async content handlers).

== Examples

=== Passthrough

[source,javascript]
----
location.addBodyFilter(async function*(chunks, req) {
    for await (var chunk of chunks) {
        yield chunk;
    }
});
----

=== Prefix / suffix injection

[source,javascript]
----
location.addBodyFilter(async function*(chunks, req) {
    yield '<!-- begin -->\n';
    for await (var chunk of chunks) {
        yield chunk;
    }
    yield '\n<!-- end -->';
});
----

=== Request-aware transformation

[source,javascript]
----
location.addBodyFilter(async function*(chunks, req) {
    for await (var chunk of chunks) {
        if (req.headers['accept-encoding']?.includes('custom')) {
            yield customEncode(chunk);
        } else {
            yield chunk;
        }
    }
});
----

=== Async fetch and inject

[source,javascript]
----
location.addBodyFilter(async function*(chunks, req) {
    // Wait for a timer (stand-in for any async I/O)
    await nginx.setTimeout(5);
    yield '[injected] ';
    for await (var chunk of chunks) {
        yield chunk;
    }
});
----

=== Empty generator (drop body)

[source,javascript]
----
location.addBodyFilter(async function*(chunks, req) {
    for await (var chunk of chunks) {
        /* consume but yield nothing — output body is empty */
    }
});
----

== Limitations (P5)

* **Whole-body buffering required**: the complete upstream body is buffered
  before the generator is called.  This is the same trade-off as `'wholeBodySync'` /
  `'wholeBodyAsync'` modes.
* **Single chunk per request**: `chunks` always yields exactly one element
  (the complete body).  Multiple-chunk streaming input is a future extension.
* **String output only**: yield values must be strings.  Other JS values are
  coerced via `.toString()`.

== Implementation Notes

The async generator mode is implemented as `NGX_JS_FILTER_GENERATOR = 4`.
It shares the whole-body buffering path (`body_filter_has_wb = 1`).

After buffering, `ngx_js_body_filters_run` wraps `body_val` in a one-element
JS array `[body_val]` and calls `fn(chunks, req)`, which returns a generator
object (`gen`).  `gen.next()` is then called iteratively:

* If `gen.next()` resolves synchronously with `done=false`, the yielded value
  is appended to the output chain and `gen.next()` is called again immediately.
* If `gen.next()` returns a pending Promise, the request is suspended (hold
  count++) and stored in an extended `ngx_js_bf_pending_t` with the `gen`
  field set.  `ngx_js_bf_async_check` resumes driving the generator when the
  Promise settles via `ngx_js_gen_drive()`.
* If `gen.next()` resolves with `done=true`, the accumulated output chain is
  sent downstream.

`ngx_js_bf_pending_t` extension fields:

[cols="1,3"]
|===
| `gen`          | Generator object (JS_UNDEFINED for non-generator entries)
| `gen_out`      | Output chain head — yielded chunks accumulate here
| `gen_out_last` | Tail pointer for O(1) append
|===
