  Stage 25 proposal — nginx.http.variables (read all nginx variables)

  Expose nginx.http.variables as a plain JS object (computed at init time) mapping every variable name registered in nginx's variables hash to its current (config-phase) value. Config-phase variables
   like $nginx_version, $hostname, $pid are available; runtime variables (per-request) would show their default/empty value.

  This gives JS scripts visibility into the full variable namespace at startup for introspection or building lookup tables.

  Implementation: iterate cmcf->variables (ngx_array_t of ngx_http_variable_t), call v->get_handler(r_dummy, vv, v->data) for variables with a get_handler, build a JS object.

  Actually, a cleaner alternative: expose it on the nginx.http object as a read-only property. Magic getter that builds the object on demand.

  Shall I proceed?
