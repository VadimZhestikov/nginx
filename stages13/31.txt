  Stage 31 — r.proxyPass(upstream)

  Allow a JS handler to proxy the current request to an upstream or URL:

  r.proxyPass('http://127.0.0.1:8081')     // proxy to backend
  r.proxyPass('upstream_name')             // proxy to named upstream

  This requires setting up an upstream on the fly, which is complex in nginx's module architecture. A simpler but still useful alternative:

  Stage 31 — nginx.http.upstreams[i].peers mutation at request time

  Allow adding/removing peers from a running upstream from a request handler (already partly possible via the existing COM, but may need live ngx_http_upstream_rr_peers_t updates).

  Or something more tractable:

  Stage 31 — r.respond() streaming / r.write() + r.finish()

  Split the response into chunks:
  r.write('chunk 1')      // sends body chunk (headers sent on first write)
  r.write('chunk 2')
  r.finish()              // sends last_buf, finalizes request

  This enables streaming responses without buffering the entire body in JS first.
