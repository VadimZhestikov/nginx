│ Plan: SharedWorker class for nginx JS module                                 │
│                                                                              │
│ Context                                                                      │
│                                                                              │
│ new SharedWorker(script) creates a long-lived JS thread (in the master       │
│ process, before fork) that all nginx worker processes can communicate with   │
│ via                                                                          │
│ pre-allocated pipe pairs.  Unlike the per-request Worker (which lives in the │
│ worker process), the SharedWorker thread persists until master exits and its │
│ state is shared across all request handlers across all nginx workers.        │
│                                                                              │
│ Architecture                                                                 │
│                                                                              │
│ Master process (init_conf phase)                                             │
│   new SharedWorker("sw.js")                                                  │
│     ├── channels[0..N-1]: each has inbox(worker→SW) + outbox(SW→worker)      │
│ pipes                                                                        │
│     └── pthread → SW thread (polls all inbox[i].rfd, handles                 │
│ onconnect/onmessage)                                                         │
│                                                                              │
│ After fork: worker[i] inherits all pipe fds (OS-level, survive fork)         │
│   First new SharedWorker(url) in worker[i]:                                  │
│     ├── activate: ngx_get_connection(channels[i].outbox.rfd) → nginx epoll   │
│     ├── pipe_send(channels[i].inbox, CONNECT sentinel)                       │
│     └── return JS SharedWorker object                                        │
│                                                                              │
│ SW thread receives CONNECT for channel i:                                    │
│     └── fire onconnect({ ports: [port_i] })  (port_i.postMessage →           │
│ outbox[i])                                                                   │
│                                                                              │
│ Request handler sets sw.onmessage = fn → stored in                           │
│ worker_slots[wi].on_message                                                  │
│ Request handler calls sw.postMessage(data) → pipe_send(channels[wi].inbox,   │
│ …)                                                                           │
│                                                                              │
│ nginx event fires on outbox[wi].rfd:                                         │
│     └── deserialize, call worker_slots[wi].on_message({data:…}),             │
│         drain microtasks, async_check                                        │
│                                                                              │

│                                                                              │
│ Two shared worker scripts (echo_sw.js, add_sw.js) using onconnect +          │
│ port model.  init.js calls new SharedWorker(…) twice in master scope         │
│ (creates two SW threads).  Two locations handled by request-level handlers   │
│ that also call new SharedWorker(url) (connects to existing one in worker).   │
│                                                                              │
│ Assertions:                                                                  │
│ like(http_get('/sw_echo/'), qr/200 OK/,  'shared worker echo 200');          │
│ like(http_get('/sw_echo/'), qr/EchoOK/,  'shared worker echo body');         │
│ like(http_get('/sw_add/'),  qr/200 OK/,  'shared worker add 200');           │
│ like(http_get('/sw_add/'),  qr/42/,       'shared worker add result');       │
│                                                                              │
│ Critical details                                                             │
│                                                                              │
│ - GC safety: worker_slots[wi].on_message is a C JSValue unknown to QJS       │
│ GC. Freed explicitly in exit_process before JS_FreeContext. The SW           │
│ opaque has no JSValue fields (state is a C pointer), so no GC cycle.         │
│ - Idempotent activation: ws->conn != NULL guard prevents double-call of      │
│ ngx_get_connection on the same fd.                                           │
│ - recv_ctx lifetime: allocated at activation; freed in exit_process (via     │
│ ws->conn->data before clearing ws->conn).                                    │
│ - nchannels: from ccf->worker_processes; clamped to [1, NGX_MAX_PROCESSES].  │
│ Workers may call new SharedWorker(url) with ngx_worker < nchannels.          │
│ - Multiple concurrent requests: both share worker_slots[wi].on_message;      │
│ last setter wins. Test uses sequential requests — document limitation.       │
│ - Thread safety: SW thread only touches its own JSRuntime/JSContext and      │
│ the mutex-protected pipe API. Never touches nginx internals or worker_slots. │
│ - Dup-before-call: ngx_js_sw_recv_handler dups ws->on_message before         │
│ JS_Call, same pattern as the Worker fix.                                     │
