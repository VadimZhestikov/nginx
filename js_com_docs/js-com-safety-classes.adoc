= COM Mutation Safety Classes
:toc: left
:toclevels: 3
:source-highlighter: rouge

Layer 1 of the operator-facing dynamic-reconfiguration plan: a per-member
classification of every settable COM property/method, plus the
`nginx.describe()` API that exposes it.  Layer 2 (policy plugins) and Layer 3
(snapshot-centric admin console) build on this metadata.

NOTE: This is a design specification.  The classification tables below are
authoritative for the implementation; the C-side `ngx_js_member_class_t`
tables must match them member-for-member.

== Why a taxonomy

The COM lets JavaScript mutate live nginx configuration, but "can I change
this safely?" has three independent answers that today live only in C comments
and the authors' heads:

. *Can I undo it?* — a scalar weight change is reversible; binding a socket is not.
. *Who sees it?* — most writes land in the calling worker's copy-on-write
  memory only; a few are cross-worker; the rest need explicit fan-out.
. *Can I scope it to one request?* — some setters honour `setWriteMode('local')`,
  most don't.

An operator cannot be expected to know that `peer.weight =` on a *zoned*
upstream is one-and-done, but the identical call on a non-zoned upstream
silently affects 1 of N workers.  The taxonomy makes all three answers
machine-readable.

== Design principle

Safety is a property of each *member*, not of the object — `NginxServer` has
safe scalar setters *and* an irreversible `addServer`-adjacent topology surface.
So the classification attaches to each settable member, and `settable()` /
`describe()` (already per-member) are the natural place to expose it.

Three orthogonal axes:

[cols="1,3", options="header"]
|===
| Axis | Question it answers

| `class`         | Reversibility + blast radius — the operator traffic light
| `propagation`   | How a change reaches the *other* workers (the COW-trap axis)
| `requestScoped` | Can it be confined to a single request via `setWriteMode('local')`?
|===

`reversible` is carried explicitly too (derived from `class`) so consumers
don't have to hard-code the mapping.

`callable` is carried for the same reason: `type: "function"` covers both a
method you call (`addHook()`) and a slot you assign a function to
(`location.handler = fn`), and only the registry knows which — it is the same
distinction that decides whether a member appears in `settable()`.

== Axis 1 — `class` (traffic light)

[cols="1,3,1", options="header"]
|===
| Class | Meaning | Reversible

| 🟢 `safe`
| Value-only mutation.  No effect on request routing, listeners, or process
  topology.  `snapshot()` / `restore()` replays the setter cleanly.
| Yes

| 🟡 `guarded`
| Reversible, but changes request *dispatch* or live protocol state, is
  timing-sensitive (in-flight requests may not observe it consistently), and is
  only meaningful once fanned out to all workers.
| Yes, with care

| 🔴 `irreversible`
| Cannot be undone for the lifetime of the process.
| *No*

| `readonly`
| Getter only — no mutation.  Listed for completeness; carries no other axes.
| n/a
|===

Classification rule for any member not in the tables below: a pure
getter/setter over a C scalar or pool-backed list is `safe`; anything that
calls `rebuild_loc_tree`, rewires dispatch, or binds/unbinds a socket is
`guarded` or `irreversible`.

== Axis 2 — `propagation` (the COW trap, made visible)

[cols="1,3", options="header"]
|===
| Value | Meaning

| `auto-shared`
| Written to a shared-memory zone; every worker observes it immediately, no
  fan-out required.  Only `nginx.shared.*` keys.

| `zoned-shared`
| Cross-worker *only if* the upstream is zone-backed (`peers->shpool != NULL`,
  i.e. `upstream.zone != null`).  Otherwise behaves as `worker-local`.
  `describe()` resolves this live per upstream.

| `worker-local`
| Copy-on-write write — lands in the *calling worker only*.  Requires explicit
  SharedWorker fan-out to apply on every worker.  *This is the default for
  nearly every COM write.*
|===

== Axis 3 — `requestScoped`

`true` for members whose setter honours `setWriteMode('local')` by deep-copying
the module conf into `r->pool` via `ngx_js_ensure_module_snapshot` /
`ngx_js_ensure_core_snapshot`.

Verified set (only these): *core `NginxLocation` scalars, `NginxHeaders`,
`NginxProxy`, `NginxGzip`, `NginxRewrite`*.  Every other sub-object is
global-only.  `location.handler` is `false` even on `NginxLocation` because it
is hard-wired to always-global dispatch (`ngx_js_com_http.c`, magic == 2).

== Descriptor shape

What `nginx.describe(path)` returns, one object per member:

[source,jsonc]
----
{
  "name": "weight",
  "type": "number",            // number | boolean | string | string[] | object | object[] | function
  "callable": false,           // true = a method you CALL; false = a slot you ASSIGN
  "access": "read-write",      // read-only | read-write
  "class": "safe",             // safe | guarded | irreversible | readonly
  "reversible": true,
  "propagation": "zoned-shared", // auto-shared | zoned-shared | worker-local
  "requestScoped": false,      // honours setWriteMode('local')
  "note": "Recomputes total_weight under rr_peers_wlock"
}
----

== Full per-member classification

Only *settable* members are listed (read-only members carry no safety class;
each object's read-only properties are summarised but not enumerated).  Unless
noted, scalar/list setters are `propagation: worker-local`.

=== nginx (root)

|===
| Member | Class | Propagation | reqScoped | Note

| `workerRequestTimeout` =| safe | worker-local | no | Per-request JS exec cap

`zoned-shared` collapses to `worker-local` when the upstream has no `zone`.

=== nginx.http topology + sockets

`nginx.http` is a plain JS object rather than a class instance, so `describe()`
reaches it through a hidden tag (`NGX_JS_DTAG_HTTP`, stamped by
`ngx_js_describe_tag()`) instead of a `JSClassID`.  Its topology methods are now
classified — closing the honesty gap where an operator could call an
irreversible method the safety layer didn't flag.

[cols="2,1,1,3", options="header"]
|===
| Member | Class | Propagation | Note
| `addServer()`       | 🔴 irreversible | worker-local | `cscf` committed in `cycle->pool`, never reclaimed
| `removeServer()`    | 🟡 guarded      | worker-local | Tombstone, reversible via `restoreServer()` (Track S); `{hard:true}` splices irreversibly
| `restoreServer()`   | 🟡 guarded      | worker-local | Clears a `removeServer` tombstone
| `attach()`          | 🔴 irreversible | worker-local | fd enters append-only `cycle->listening`, fork-inherited
| `removeListener()`  | 🟡 guarded      | worker-local | Soft pause, reversible via `restoreListener()` (Track N); `{hard:true}` closes the socket irreversibly
| `restoreListener()` | 🟡 guarded      | worker-local | Re-arms a soft-paused listener; returns `false` after a hard close
| `addHook()`         | 🟡 guarded      | worker-local | Global access-phase hook
|===

The created-socket handle (`NginxSocket`: `close()`/`broadcast()`), the listener
handle (`NginxHttpListener`: `addServer`/`addVirtualServer` 🔴, hook/filter
registrations 🟡), the HTTP `NginxUpstream` (`addPeer`/`removePeer` 🟡
zoned-shared), `nginx.cycle.workers` (🟡), and `NginxSnapshot.restore()` (🟡)
are all classified too — they are real class instances reached by `JSClassID`.

=== NginxStream

Mirror the HTTP classifications: stream server/proxy/ssl scalar setters are
`safe`/`worker-local`; stream peer scalars are `zoned-shared`; `attach()` /
listener binding is `irreversible`.

== API surface (backward-compatible)

[cols="2,3", options="header"]
|===
| Call | Returns

| `nginx.settable(path)`        | `string[]` of *assignable* member names.  Now covers every class `describe()` classifies (not just the seven snapshot-backed ones) — the assignable members are exactly the describe() members that are not callable methods (`NGX_JS_MF_METHOD`).  So `settable() ⊆ describe()` for every class, with no drift.
| `nginx.describe()`            | discovery root — `[{ class, members[] }]` for every classifiable COM class (so tooling can enumerate what exists before drilling in)
| `nginx.describe(path)`        | `Descriptor[]` for every member at `path` — settable/mutating members (from the class table) **and** read-only getters (discovered from the prototype, `class:"readonly"`), so it is a complete per-object reference
| `nginx.describe(path, name)`  | single-member `Descriptor`, or `null`
|===

Read-only members are listed but their getter is **not** invoked by `describe()`
(no side effects, and some getters touch unconfigured module state and would
crash if called outside a matching request).  Their `type` instead comes from a
static name→type map of the verified inspection getters (`path`→`string`,
`headerFilters`→`object[]`, `port`→`number`, …); anything not in the map falls
back to `type:"getter"` with an explanatory note (still honest — it is a
read-only accessor to drill into).

`path` accepts the same syntax as `nginx.get`/`set`
(e.g. `"http.upstreams[0].peers[0]"`, `"http.servers[0].locations[2].proxy"`).

`describe()` resolves `propagation` with a *runtime refinement hook* where the
answer is conditional: upstream peer members check `uscf->shm_zone` live so a
zoned upstream reports `zoned-shared` and a plain one reports `worker-local`.
All other members are a static lookup.

== C-side storage (hybrid)

One static table per COM class file, placed next to the proto table it
describes so a setter and its classification cannot drift:

[source,c]
----
typedef struct {
    const char  *name;
    uint8_t      klass;        /* NGX_JS_SAFE | _GUARDED | _IRREVERSIBLE | _READONLY */
    uint8_t      flags;        /* NGX_JS_MF_REVERSIBLE | _REQUEST_SCOPED | _METHOD */
    uint8_t      propagation;  /* static default: AUTO_SHARED | ZONED_SHARED | WORKER_LOCAL */
    const char  *note;
} ngx_js_member_class_t;
----

`klass`, `reversible`, and `requestScoped` are static facts of the setter and
never need runtime refinement.  `propagation` carries a static default; an
optional per-class `refine(op, member)` callback overrides it (only upstream
peers need one today).  A shared helper `ngx_js_describe_members(ctx, op,
table, n)` builds the descriptor array for any object.

TIP: For the end-to-end recipe of adding a *new* COM class (the bridge file,
the class registration, and the three describe-side additions — member table,
registry row, catalog row — plus the `NGX_JS_MF_METHOD` gotcha), see
*"Third-Party Module Integration"* in `js-dom-manual.adoc`.

== How Layers 2 & 3 consume it

* *Policy plugins (Layer 2):* a safe-operation library asserts on `class`
  before acting — refuse to expose `irreversible` members as casual toggles,
  and auto-wire SharedWorker fan-out for any `worker-local` write.
* *Admin console (Layer 3):* render each pending op with its `class` colour;
  gate `irreversible` behind explicit confirmation; show `worker-local` ops
  next to fan-out ACK / convergence state so the COW trap is visible rather
  than silent.

== Layer 2 — the `safe-config` policy plugin

*Implemented* — `js_com_apps/safe_config/` (a reusable `nginx.use()` plugin
that installs `nginx.safeConfig`).  It is the safety gateway over the Layer 1
metadata: every mutation consults `describe()`, is gated by tier, and is routed
by propagation.

[source,javascript]
----
nginx.use('./js_com_apps/safe_config',
          { cfgWorkerPath: '<abs>/js_com_apps/safe_config/cfgworker.js' });

// Gateway: describe() → gate → apply → fan-out (if worker-local)
nginx.safeConfig.apply(path, value [, opts]);
nginx.safeConfig.plan(path, value);          // dry-run; returns the plan, no mutation

// Named policies (vetted vocabulary built on apply())
nginx.safeConfig.canaryWeight(upstream, pct [, opts]);       // weight split
nginx.safeConfig.setResponseHeader(server, loc, key, val);    // headers.addHeaders
nginx.safeConfig.toggleLocation(server, loc, on [, opts]);    // 503 ↔ restore
nginx.safeConfig.drainPeer(upstream, addr [, opts]);          // peer.down = true
----

*Per-tier opt-in (default):*

[cols="1,2", options="header"]
|===
| class | required opt-in
| `safe`         | none
| `guarded`      | `{ ack: true }` (else throws, quoting the descriptor note)
| `irreversible` | `{ confirm: true }`
|===

*Propagation routing:* the gateway fans a write out to all workers (via the
plugin's `cfgworker.js` SharedWorker) only when `describe()` reports
`worker-local`.  `zoned-shared` / `auto-shared` writes apply directly — and
because `describe()` resolves zoned-vs-not live, the same `peer.weight` write
auto-fans-out on a non-zoned upstream and applies directly on a zoned one.

*Fan-out payloads are JSON-serialisable* (`{kind:'set', path, value}` or
`{kind:'toggle', …}`).  `toggleLocation` can't serialise a handler function, so
it fans out a `toggle` command and each worker saves/restores its own prior
handler locally (symmetric enable/disable).

Without `cfgWorkerPath`, writes apply to the calling worker only and plans
report `fannedOut:false` — fine for single-worker setups.

Demo: `A0.3_Safe_config_actuator` (REST actuator; 14-check cross-worker test).
Tests: `t/js_safe_config.t`.

== Layer 3 — the snapshot-centric admin console

*Implemented* — `js_com_demos/A4_Interactive_Operations/A4.1_Admin_console`.
The operator-facing surface that composes the whole plan on one screen:

* *History + diff* — the A2.7 admin engine (snapshots, apply / rollback /
  squash, reset-to-base, fan-out) is reused verbatim as the backend.
* *Safety annotation (L1)* — every op in a snapshot is resolved through
  `nginx.describe()` and rendered with its class colour (🟢 / 🟡 / 🔴),
  propagation, and note.
* *The gate (L2)* — `POST /c/apply` returns *409* (listing the blocking ops)
  when a snapshot contains `irreversible` ops and `confirm=1` is absent; the UI
  turns that into a confirm dialog.
* *Convergence — the COW trap made visible* — each worker stamps the snapshot
  id it has applied into `nginx.shared` (`sc.cv.<workerIdx>`); the console
  compares every stamp to `sc.cv.desired` and shows which worker PIDs have
  caught up and which are still lagging.  This is the only addition to the
  otherwise-verbatim A2.7 engine (a stamp at the apply seam).

The console proves the thesis of the whole document: operators interact with
*history, colored diffs, a safety gate, and convergence state* — never with raw
`nginx.*` paths or the knowledge of which writes need fan-out.

Demo / test: `A4.1_Admin_console/test.sh` (20 checks — annotation, the 409 gate,
apply + 4-worker convergence, rollback, the confirm override, and a reversible
removeLocation hide → rollback → restore round trip).

== Making "irreversible" reversible — Track L (locations)

The four-levels-of-symmetry analysis (config-state / resource / identity /
effect) concluded that *config-state* reversibility is the operator contract and
is achievable for almost everything.  Track L delivers it for locations:

* `removeLocation(path)` now **tombstones** by default — the entry is excluded
  from the live tree but kept (clcf preserved), so `restoreLocation(path)` is a
  true inverse with *identity preserved* (same handler/config object).  This is
  the same memory profile as the old splice (which also never freed), so it is a
  strict improvement.  `{hard:true}` keeps the legacy irreversible splice.
* Reclassified 🔴 → 🟡 *guarded* (`reversible:true`).  The `note` records what
  rollback does **not** undo: in-flight 404s emitted while hidden (the *effect*
  asymmetry), and that a `{hard:true}` splice is one-way.
* The admin engine restores tombstones on reset-to-base, so rollback is
  symmetric (`A4.1` hides `/api/` via a snapshot, then rollback brings it back
  across all workers).

[NOTE]
====
*Object-or-key ergonomics.*  `removeLocation` / `restoreLocation`,
`removeServer` / `restoreServer` and `removeListener` / `restoreListener` accept
*either* the key string they always took *or* the COM object the matching
`add*()` / `createSocket()` returned, so `x = srv.addLocation('/p/', fn);
srv.removeLocation(x)` works as well as `srv.removeLocation('/p/')`.  The key is
read off the object — location `.pattern`, server `.name`, socket `.address`
(`ngx_js_coerce_key_arg`).  The keyed form stays canonical for snapshot replay
(ops resolve by stable name, not object identity).
====

**Track S (servers)** applies the same tombstone pattern:
`nginx.http.removeServer(name)` now drops the server's names from the
virtual-server hash (a module-side tombstone set that `rebuildVhostDispatch`
skips) while keeping the `cscf` + wrapper, so `restoreServer(name)` is a true
inverse.  Both auto-rebuild the dispatch.  `{hard:true}` keeps the legacy
splice.  The admin console restores soft-removed servers on reset-to-base, so a
`removeServer` snapshot round-trips under rollback (A4.1 hides `ghost.local`
then restores it across all workers).

**Track N (listeners)** applies the same pattern with a socket twist:
`nginx.http.removeListener(addr)` *soft-pauses* — `ngx_del_event` removes the
worker's accept event so it stops accepting (the fd stays bound; new
connections queue in the kernel backlog rather than being refused);
`restoreListener(addr)` re-arms it (`ngx_add_event`).  Per-worker, fanned out by
the admin console (A4.1 pauses/resumes `:8136` across all workers via snapshot +
rollback).

`removeListener(addr, {hard:true})` *truly closes* the listener (🔴
irreversible).  Every worker retires its own fd (`ngx_del_event` + a `/dev/null`
`dup2` that releases the open-file-description while keeping a harmless
descriptor so nginx's shutdown `close()` stays clean), and the master's fd is
retired by the SharedWorker *manager thread* — reached **fire-and-forget**: the
worker sends the close command with `MSG_DONTWAIT` and never waits for a reply,
so its event loop can't block on the IPC.  Once every process (workers +
master) retires the fd the open-file-description refcount hits zero, the port is
freed and new connections are refused (`ECONNREFUSED`).  `restoreListener` after
a hard close returns `false` — consistent with the `{hard:true}` variants of
`removeLocation` / `removeServer`.

NOTE: a manager-created listening socket (`createSocket`) **must** be set
non-blocking.  It bypasses nginx's `ngx_open_listening_sockets()` (which would
call `ngx_nonblocking`), and a blocking `accept()` in the event loop wedges the
whole worker (`wchan inet_csk_accept`) the moment a peer drains the shared
backlog first.  Likewise `restoreListener` must re-arm the accept event with the
*same* flags nginx used originally (`NGX_EXCLUSIVE_EVENT` / `EPOLLEXCLUSIVE` for
a non-reuseport listener under epoll with >1 worker) — re-adding level-triggered
non-exclusive causes spurious wakeups against the shared socket.  Both were real
bugs in the soft-pause path, exposed only under concurrent connection load.

`addServer` and `attach` remain 🔴 *irreversible* — their `cscf` / bound socket
are committed in `cycle->pool` and never reclaimed at runtime (the *resource*
asymmetry), even though the routing/accept *effect* can be undone with
`removeServer` / `removeListener`.  These one-way ops are now reachable by
`describe()` (via the `nginx.http` tag), so the safety layer flags them directly
rather than relying on the console's annotation map.

== Settled design decision — `propagation` is an enum, not two booleans

`propagation` is exposed as a single enum (`worker-local` / `zoned-shared` /
`auto-shared`) rather than two booleans (`crossWorker` + `needsFanOut`).  This
was considered and **deliberately kept as the enum**:

* `zoned-shared` is a genuine third, *runtime-conditional* state — not a
  combination of the other two.  Whether a write crosses workers depends on live
  config: e.g. `peers[0].weight` is cross-worker only when its upstream has a
  `zone` directive (the slab is shared); without a zone the peer is in each
  worker's private heap and the write is worker-local.  `describe()` resolves
  this per object at call time via a propagation *refine hook*
  (`ngx_js_peer_prop_refine`), returning `zoned-shared` or `worker-local`.
* A static `crossWorker` boolean therefore cannot describe `peers[].weight`
  honestly — the truthful answer is "it depends."  Expressing that with booleans
  needs a tri-state, which is just the enum again.  `worker-local` and
  `auto-shared` are the two endpoints; `zoned-shared` is the irreducible
  conditional middle.
* The choice is representation-only (the shape of the `describe()` Descriptor)
  with no behavioural impact, and current consumers (`A4.1`, `safeConfig`) read
  the `propagation` string directly.  Revisit only if a consumer genuinely needs
  the decomposed `crossWorker` / `needsFanOut` flags.
