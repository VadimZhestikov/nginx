== Overview

The previous guide (_for single worker_) explained `write_mode`, `read_mode`,
`snapshot()`, and `restore()` — all of which operate **within a single nginx
worker process**.

This guide addresses the harder problem: propagating a config change to
**all workers simultaneously**.

Prerequisites: read the _for single worker_ guide first.

=== The multi-process problem

nginx runs as a master process plus N worker processes.  Each worker is a
separate OS process with its own address space.  After the initial fork, the
workers share _no memory_ — not even memory marked `write_mode='global'`.

[source,text]
----
                 ┌────────────────┐
                 │  Master (pid 1)│
                 │  (no requests) │
                 └────────┬───────┘
                          │ fork at startup
          ┌───────────────┼───────────────┐
          │               │               │
   ┌──────▼──────┐ ┌──────▼──────┐ ┌──────▼──────┐
   │  Worker 0   │ │  Worker 1   │ │  Worker 2   │
   │  clcf copy  │ │  clcf copy  │ │  clcf copy  │
   │  ups copy   │ │  ups copy   │ │  ups copy   │
   └─────────────┘ └─────────────┘ └─────────────┘
         │                │                │
         │  COW pages     │                │
         │  diverge on    │                │
         │  first write   │                │
         ▼                ▼                ▼
   independent copies after any write_mode='global' mutation
----

A `write_mode='global'` assignment in a request handler in Worker 0
changes Worker 0's copy of the C struct.  Workers 1 and 2 are unaffected.

=== What this guide covers

Three propagation strategies:

[cols="1,2,2"]
|===
| Strategy | How it works | Best for

| *SharedWorker broadcast*
| One long-lived pthread acts as the config authority.
  Workers push updates to it; it fans out to all workers.
| Rich config objects, arbitrary JS values, ordered delivery.

| *SharedArrayBuffer (SAB)*
| A region of memory shared across all worker processes via `mmap`.
  Workers write/read with `Atomics` for synchronisation.
| Numeric parameters (weights, timeouts), high-frequency updates.

| *Periodic reconciliation*
| Each worker polls the SharedWorker for the desired config state
  and applies any diff on each poll tick.
| Eventual consistency is acceptable; simpler code.
|===

== suspendAllWorkers() and resumeAllWorkers()

=== The atomicity problem

The broadcast strategies in this guide deliver _eventual_ consistency:
there is a window between when Worker 0 applies a change and when Worker N
applies the fan-out.  During that window different workers may have different
configs.

For changes that must be visible consistently across all workers before any
new request is accepted, use `nginx.suspendAllWorkers()` and
`nginx.resumeAllWorkers()`.

=== How they work

`await nginx.suspendAllWorkers()` sends a command to the nginx master
process.  The master broadcasts "suspend acceptance" to every worker and
waits for acknowledgements (up to a 500 ms timeout).  The Promise resolves
when *all* workers have disabled their accept events.

`await nginx.resumeAllWorkers()` sends the reverse command.  All workers
re-enable accept events.

Both calls are *async* and return `Promise<undefined>`.  The handler must
be declared `async` and must `await` both calls.  Always use `try/finally`
to guarantee `resumeAllWorkers()` is called even on error.

NOTE: `suspendAllWorkers()` is callable only from a worker process — not
from config phase or from a Worker/SharedWorker thread.

=== Flow diagram

The broadcast to other workers is *asynchronous*.  `cfgWorker.postMessage()`
returns immediately; fan-out messages are delivered to each worker's event
loop in a subsequent iteration.  To guarantee all workers have applied before
any new connection is accepted, the handler must **await an acknowledgement**
from every fan-out recipient before calling `resumeAllWorkers()`.

[source,text]
----
  Worker 0 (handler):        SharedWorker:        Workers 1…N:

  await suspendAllWorkers()
  ────────────────────────────────────────────►  all suspended

  apply mutations locally

  postMessage('set') ────────► fan-out to 1…N ──►  applyChange()
                                                    postMessage('set-ack')
                               count acks ◄──────────────────────────────
                               all acked →
                               postMessage('set-complete')
  await 'set-complete' ◄─────────────────────

  await resumeAllWorkers()
  ────────────────────────────────────────────►  all resume

  All workers now hold identical config.  No request sees partial state.
----

While suspended, new TCP connections queue in the OS socket backlog
(`net.core.somaxconn`).  Keep the suspension window as short as possible —
typically synchronous field writes only, not async probes.

=== Example: atomic batch update across all workers

The cfgWorker must support an ACK protocol (`set-ack` → `set-complete`) so
the handler can confirm that every worker applied before resuming.  See the
updated `cfgworker.js` in <<_strategy_1_sharedworker_based_config_broadcast>>
below.

[source,javascript]
----
loc.handler = async (req) => {
    const cfg = JSON.parse(await req.readBody());

    // Validate BEFORE suspending — keep the suspension window short.
    const ok = await probeBackend(req);
    if (!ok) {
        req.respond(400, {}, 'validation failed');
        return;
    }

    await nginx.suspendAllWorkers();

    try {
        // Apply to this worker.
        nginx.http.upstreams[0].peers.forEach((p, i) => {
            if (cfg.weights[i] !== undefined) { p.weight = cfg.weights[i]; }
        });

        // Broadcast to all OTHER workers and wait until every worker
        // acknowledges that it has applied — then resumeAllWorkers() is safe.
        await new Promise(function (resolve) {
            cfgWorker.onmessage = function (msg) {
                if (msg.data.type === 'set-complete') { resolve(); }
            };
            cfgWorker.postMessage({ type: 'set', payload: cfg });
        });

        req.json({ applied: true });
    } finally {
        await nginx.resumeAllWorkers();    // safe: all workers applied
    }
};
----

=== Example: atomic cross-worker rollback

Both the success path (`set`) and the error path (`rollback`) fan out to other
workers; both must be awaited before `resumeAllWorkers()`.

[source,javascript]
----
loc.handler = async (req) => {
    const snap = req.location.snapshot();      // save rollback state
    const cfg  = JSON.parse(await req.readBody());

    // Validate before suspending.
    const ok = await probeBackend(req);
    if (!ok) {
        req.respond(400, {}, 'validation failed');
        return;
    }

    await nginx.suspendAllWorkers();

    try {
        req.location.root              = cfg.root;
        req.location.proxy.readTimeout = cfg.proxy.readTimeout;

        await new Promise(function (resolve) {
            cfgWorker.onmessage = function (msg) {
                if (msg.data.type === 'set-complete') { resolve(); }
            };
            cfgWorker.postMessage({ type: 'set', payload: cfg });
        });

        req.json({ applied: true });

    } catch (e) {
        snap.restore();    // revert this worker

        // Broadcast rollback and wait for all workers to revert before resume.
        await new Promise(function (resolve) {
            cfgWorker.onmessage = function (msg) {
                if (msg.data.type === 'rollback-complete') { resolve(); }
            };
            cfgWorker.postMessage({ type: 'rollback', payload: cfg });
        });

        req.respond(500, {}, e.message);

    } finally {
        await nginx.resumeAllWorkers();    // safe: all workers reverted/applied
    }
};
----

=== Per-worker atomicity (suspendAcceptance)

If only *this* worker needs an atomic batch (e.g. a local reconciliation
step), use the lighter `nginx.suspendAcceptance()` /
`nginx.resumeAcceptance()` pair instead.  These are *synchronous*, affect
only one worker, and carry zero cross-process overhead.
See the _for single worker_ guide for details.

=== API reference

[source,text]
----
Promise<undefined>  nginx.suspendAllWorkers()
Promise<undefined>  nginx.resumeAllWorkers()
----

Both throw `TypeError` if called outside a worker process, and
`InternalError` if the manager is unavailable or the reply fd cannot
be registered in the event loop.


== Strategy 1: SharedWorker-based config broadcast

=== Architecture

A `SharedWorker` runs in a dedicated pthread that is accessible to all
workers through their per-worker channel.  It holds the _desired_ config
state.  When any worker receives a config-change request, it:

1. Validates and applies the change locally (see _for single worker_ guide).
2. Posts the serialised change to the SharedWorker.
3. The SharedWorker fans out the message to all other workers.
4. Each receiving worker applies the change via `write_mode='global'`.

[source,text]
----
  HTTP request ──► Worker 0
                      │
                      ├─ validate change
                      ├─ apply locally (write_mode='global')
                      │
                      └─ postMessage(change) ──► SharedWorker (pthread)
                                                       │
                                              ┌────────┼────────┐
                                              │        │        │
                                         Worker 0  Worker 1  Worker 2
                                         (already  apply     apply
                                          done)    change    change
----

=== SharedWorker setup

Define the SharedWorker in `js_source`.  It runs once in the master at
`init_conf` and its channel is shared with every worker.

[source,javascript]
----
// js_source: config.js  (runs at init_conf, before workers fork)

const cfgWorker = new SharedWorker('cfgworker.js');

nginx.broadcast(function () {
    cfgWorker.onmessage = function (msg) {
        var type = msg.data.type;

        if (type === 'upstream.weight') {
            // Eventual-consistency fan-out — apply directly.
            applyChange(msg.data);

        } else if (type === 'set') {
            // Atomic fan-out from suspendAllWorkers context — apply and ACK.
            applyChange(msg.data.payload);
            cfgWorker.postMessage({ type: 'set-ack' });

        } else if (type === 'rollback') {
            // Atomic rollback fan-out — revert and ACK.
            applyChange(msg.data.payload);
            cfgWorker.postMessage({ type: 'rollback-ack' });
        }
    };
    cfgWorker.postMessage({ type: 'get' });   // catch up on restart
});

function applyChange(change) {
    if (!change) { return; }
    var type = change.type || 'upstream.weight';
    if (type === 'upstream.weight') {
        var ups  = nginx.http.upstreams.find(function (u) { return u.name === change.upstream; });
        if (!ups) { return; }
        var peer = ups.peers.find(function (p) { return p.address === change.peer; });
        if (!peer) { return; }
        peer.weight = change.weight;   // write_mode='global' → this worker's copy
    }
}
----

[source,javascript]
----
// cfgworker.js  (SharedWorker pthread — uses nginx onconnect/port pattern)

var desiredWeights = {};   // { 'upstream/peer': weight }
var _ports  = [];
var _pending = null;       // {sender, needed, count, completeType}

onconnect = function (e) {
    var port = e.ports[0];
    _ports.push(port);

    port.onmessage = function (ev) {
        var type    = ev.data.type;
        var payload = ev.data.payload;

        if (type === 'set') {
            // Store desired state and fan out to all OTHER workers with ACK.
            if (payload && payload.upstream && payload.peer) {
                desiredWeights[payload.upstream + '/' + payload.peer] = payload.weight;
            }
            _fanOutAndAck(port, { type: 'set', payload: payload }, 'set-ack', 'set-complete');

        } else if (type === 'set-ack') {
            _collectAck('set-complete');

        } else if (type === 'rollback') {
            // Restore previous weights and fan out with ACK.
            var prev = payload && desiredWeights[payload.upstream + '/' + payload.peer];
            var reverted = { upstream: payload.upstream, peer: payload.peer, weight: prev };
            _fanOutAndAck(port, { type: 'rollback', payload: reverted }, 'rollback-ack', 'rollback-complete');

        } else if (type === 'rollback-ack') {
            _collectAck('rollback-complete');

        } else if (type === 'get') {
            port.postMessage({ type: 'sync', state: desiredWeights });
        }
    };
};

function _fanOutAndAck(senderPort, msg, ackType, completeType) {
    var fanout = _ports.filter(function (p) { return p !== senderPort; });
    if (fanout.length === 0) {
        senderPort.postMessage({ type: completeType });
        return;
    }
    _pending = { sender: senderPort, needed: fanout.length, count: 0,
                 ackType: ackType, completeType: completeType };
    fanout.forEach(function (p) { p.postMessage(msg); });
}

function _collectAck(completeType) {
    if (!_pending || _pending.completeType !== completeType) { return; }
    _pending.count++;
    if (_pending.count >= _pending.needed) {
        _pending.sender.postMessage({ type: completeType });
        _pending = null;
    }
}
----

=== Request handler: propagate a weight change

[source,javascript]
----
loc.handler = async (req) => {
    const body   = JSON.parse(await req.readBody());
    const change = { upstream: body.upstream, peer: body.peer, weight: body.weight };

    // 1. Apply locally so this request sees the new state immediately.
    applyChange(change);

    // 2. Tell SharedWorker to fan out to all other workers (eventual consistency —
    //    no suspendAllWorkers() here; other workers converge within one event-loop tick).
    cfgWorker.postMessage({ type: 'set', payload: change });

    req.json({ applied: true });
};
----

[source,text]
----

  Worker 0: receives /admin/set-weight
    ├─ applyChange(change)     ← local apply
    └─ cfgWorker.postMessage() ─────────────────► cfgWorker pthread

                                                   │         │

=== Snapshot + broadcast: rollback across all workers

If validation fails after applying locally, roll back locally **and**
broadcast a rollback message.

[source,javascript]
----
loc.handler = async (req) => {
    const body   = JSON.parse(await req.readBody());
    const snap   = req.location.snapshot();        // save current state

    try {
        applyChange(body);                          // apply locally
        const ok = await probeBackend(req);
        if (!ok) { throw new Error('probe failed'); }

        cfgWorker.postMessage({ type: 'set', payload: body });
        req.json({ applied: true });

    } catch (e) {
        snap.restore();                             // revert local copy

        // Broadcast rollback (SharedWorker restores original desired state)
        cfgWorker.postMessage({ type: 'rollback', payload: body });
        req.respond(500, {}, 'apply failed: ' + e.message);
    }
};
----

The SharedWorker's `rollback` branch (shown in the full `cfgworker.js` above)
restores `desiredWeights` to the previous value and fans the original weight
back to all other workers.  Both the `set` and `rollback` postMessage calls
here are fire-and-forget (no `suspendAllWorkers`) — this is an
*eventual-consistency* rollback.

NOTE: Between the `set` fan-out and the `rollback` fan-out there is a brief
window where some workers may have the new value and others the old one.
This is inherent to eventual-consistency approaches and is acceptable for
most configuration use cases.  For strict atomicity combine with
`suspendAllWorkers()` as shown in sections 2.4 and 2.5.

== Strategy 2: SharedArrayBuffer (SAB) for numeric parameters

=== When to use SAB

`SharedArrayBuffer` provides shared memory visible to all worker processes
simultaneously.  Combined with `Atomics`, it gives synchronous, lock-free
reads and compare-and-swap writes without any message passing.

Use SAB for high-frequency, low-latency updates of numeric parameters:
upstream peer weights, timeout values, rate limits.

=== SAB-backed weight array

[source,javascript]
----
// js_source: sab_config.js

// Create a SAB in the master (before fork).
// Layout: one Int32 slot per upstream peer, indexed by peer position.
const PEER_COUNT = 8;
const weightBuf  = new SharedArrayBuffer(PEER_COUNT * 4);
const weights    = new Int32Array(weightBuf);

// Initialise from current nginx config
nginx.http.upstreams.forEach(ups => {
    ups.peers.forEach((p, i) => {
        Atomics.store(weights, i, p.weight);
    });
});

// Worker handler: read-modify-write a single peer weight
function setWeight(peerIdx, newWeight) {
    Atomics.store(weights, peerIdx, newWeight);

    // Apply to this worker's nginx struct immediately
    const peer = nginx.http.upstreams[0].peers[peerIdx];
    if (peer) { peer.weight = newWeight; }
}

// Worker handler: apply all SAB values to this worker's structs
// (call periodically or on a trigger to "sync" this worker)
function syncWeightsFromSAB() {
    nginx.http.upstreams[0].peers.forEach((p, i) => {
        const desired = Atomics.load(weights, i);
        if (p.weight !== desired) { p.weight = desired; }
    });
}
----

=== Periodic sync trigger

Workers cannot pro-actively receive SAB updates — they must poll.
Use `nginx.setTimeout` to schedule a periodic sync:

[source,javascript]
----
// js_source: start a reconciliation loop in every worker
(async function reconcileLoop() {
    while (true) {
        await nginx.setTimeout(1000);   // every 1 s
        syncWeightsFromSAB();
    }
})();
----

=== Atomic compare-and-swap for safe weight update

[source,javascript]
----
loc.handler = (req) => {
    const idx        = parseInt(req.getVar('arg_idx'));
    const newWeight  = parseInt(req.getVar('arg_weight'));
    const expected   = parseInt(req.getVar('arg_expected'));  // CAS guard

    const actual = Atomics.compareExchange(weights, idx, expected, newWeight);

    if (actual !== expected) {
        req.respond(409, {}, 'CAS failed: weight changed by another worker');
        return;
    }

    // CAS succeeded — apply locally; other workers will pick it up on next poll
    const peer = nginx.http.upstreams[0].peers[idx];
    if (peer) { peer.weight = newWeight; }

    req.json({ applied: true, prev: actual });
};
----

== Strategy 3: Periodic reconciliation

=== Pattern

Rather than reacting to change events, each worker independently polls a
SharedWorker (the "config authority") and applies any diff.

[source,javascript]
----
// js_source: reconcile.js

const cfgAuth = new SharedWorker('cfgauth.js');
let desiredConfig = null;   // cached desired state (updated by onmessage)

cfgAuth.onmessage = (msg) => {
    desiredConfig = msg.data.config;
};

// Request desired config from authority at startup
cfgAuth.postMessage({ type: 'get' });

// Reconciliation loop: every 5 s, apply diff
(async function reconcileLoop() {
    while (true) {
        await nginx.setTimeout(5000);
        if (!desiredConfig) { continue; }

        nginx.http.upstreams.forEach(ups => {
            const desired = desiredConfig.upstreams?.[ups.name];
            if (!desired) { return; }

            ups.peers.forEach((p, i) => {
                const dw = desired.peers?.[i]?.weight;
                if (dw !== undefined && p.weight !== dw) {
                    p.weight = dw;
                }
            });
        });
    }
})();
----

[source,javascript]
----
// cfgauth.js  (SharedWorker — single source of truth)

let config = { upstreams: {} };

onmessage = (msg) => {
    if (msg.data.type === 'set') {
        // Deep-merge incoming change into desired config
        merge(config, msg.data.config);
        postMessage({ type: 'config', config });   // broadcast to all workers

    } else if (msg.data.type === 'get') {
        postMessage({ type: 'config', config });   // reply to requester
    }
};

function merge(target, src) {
    for (const k of Object.keys(src)) {
        if (src[k] && typeof src[k] === 'object' && !Array.isArray(src[k])) {
            target[k] = target[k] || {};
            merge(target[k], src[k]);
        } else {
            target[k] = src[k];
        }
    }
}
----

== Caveats and best practices

=== Eventual consistency

All three strategies deliver *eventual* consistency.  Between the moment a
change is initiated and the moment all workers have applied it there is a
window during which workers may disagree.

For most config-change use cases (upstream weights, timeouts, feature flags)
this is acceptable.  For strict consistency, use a coordinated handshake:

[source,javascript]
----
// Worker 0 waits for acknowledgement from all other workers before
// considering the change applied.
// (Implementation depends on the SharedWorker protocol design.)
----

=== In-flight requests during a config change

Requests that started before the config change will complete with the old
config values.  This is intentional — mid-request config changes are never
applied retroactively.

=== Worker restart behaviour

When a worker crashes and is restarted by the master, the new worker forks
from the master's original config.  It will not automatically pick up
runtime mutations applied to sibling workers unless it receives a
reconciliation message from the SharedWorker or re-reads a SAB.

A healthy reconciliation loop (Strategy 3) handles this automatically:
the restarted worker will catch up within one poll period.

=== Ordering guarantees

The SharedWorker pthread processes messages sequentially (one at a time).
Fan-out is also sequential.  Workers may apply fan-out messages in different
orders if they happen to be busy when the message arrives — do not rely on
cross-worker ordering.

=== Config-phase mutations (init_conf)

Config-phase mutations (in top-level `js_source` code, before `loc.handler`
is set) run in the master before fork.  They are inherited by all workers at
fork time and require no broadcast.  Only _request-phase_ mutations need
the strategies described in this guide.

=== Example: add_header injection with Strategy 1 broadcast

`location.headers.addHeader()` / `removeHeader()` / `addHeaders=[]` mutate
a location's `add_header` config list on the *current worker* only.  This is a
concrete case for Strategy 1: an admin endpoint applies the change locally then
fans it out via a lightweight SharedWorker bus.

[source,javascript]
----
// cfgbus.js  — broadcast bus SharedWorker
var _ports   = [];
var _current = [];  // canonical current state

function apply(msg) {
    if (msg.type === 'addHeader')
        _current.push({key:msg.key, value:msg.value, always:!!msg.always});
    else if (msg.type === 'removeHeader')
        _current = _current.filter(h => h.key.toLowerCase() !== msg.key.toLowerCase());
    else if (msg.type === 'clearHeaders')
        _current = [];
}

onconnect = e => {
    var port = e.ports[0];
    _ports.push(port);
    port.postMessage({type:'setState', headers:_current.slice()});  // catch-up
    port.onmessage = ev => {
        apply(ev.data);
        _ports.forEach(p => { if (p !== port) p.postMessage(ev.data); });
    };
};
----

[source,javascript]
----
// handler.js  (nginx.broadcast runs in every worker)
nginx.broadcast(() => {
    const locs    = nginx.http.servers[0].locations;
    const appLoc  = locs.find(l => l.path === '/app/');
    const cfgBus  = new SharedWorker(nginx.cycle.prefix + 'cfgbus.js');

    // Receive fan-out mutations from other workers
    cfgBus.onmessage = e => {
        const m = e.data;
        if (m.type === 'setState')
            m.headers.forEach(h => appLoc.headers.addHeader(h.key,h.value,h.always));
        else if (m.type === 'addHeader')
            appLoc.headers.addHeader(m.key, m.value, m.always);
        else if (m.type === 'removeHeader')
            appLoc.headers.removeHeader(m.key);
        else if (m.type === 'clearHeaders')
            appLoc.headers.addHeaders = [];
    };

    // Admin endpoint
    locs.find(l => l.path === '/admin/header/').handler = req => {
        const key = (req.queryParams?.key   || '').trim();
        const val = (req.queryParams?.value || '').trim();
        appLoc.headers.addHeader(key, val);        // local, immediate
        cfgBus.postMessage({type:'addHeader', key, value:val, always:false});
        req.respond(200, {}, JSON.stringify({ok:true}));
    };
});
----

Key points:

* The sender applies locally first (immediate) then fans to others (skip-self pattern in the SW).
* The SW maintains the canonical state so a restarted worker receives `setState` on connect and catches up.
* `/app/` needs *no JS content handler* — it can be `proxy_pass`, `return`, or a static location.

Full working demo: `js_com_demos/A2_Cross_Worker_Coordination/A2.8_Live_header_mutation/`.
